Bound daily posting work and route planning without synchronous frame escapes

Refs #90

The frame advancement budget previously surrounded whole-minute posting batches and could switch a repeatedly restarted citizen route into unlimited synchronous work. This change caps posting units at 32 and keeps all route replays finite, preserving the original logical event barrier and money/meal ordering. The posting queue reuses heap slots with cached ordinal ranks/due times instead of allocating one sorted-set node per posting.

Finite native route jobs admit at most eight stages and one NavMesh path calculation per call, two job path calculations per planner/frame; road continuations admit one 64-expansion slice. Genuine input-version changes discard the working event and replay it in bounded slices. Permanent churn can still hold the clock; F1 owns overload/backpressure. Advance planning/versioned-input investigation is documented without speculative event reordering.

Campaign observation now admits **one atomic boundary unit of at most 64 retained shop scopes**. Above 64 it refuses the whole hour before reader binding/scans, retains old evidence, and exposes refusal counters. This is an explicit native-coherence/admission limit: it narrows automatic observation coverage, does not change business ownership, and does not claim to have refreshed 1,024 businesses. Native/UI fields cannot safely be suspended across frames under the verified contract. The wider saved/diagnostic envelope stays intact.

**Schema unchanged (25 on this base).** Posting indexes and route working copies are transient/re-derived from existing saved timestamps/ledgers and the unstarted event. No persisted cursor, RLO change, accounting-epoch policy or work on the four parked hotspots.
