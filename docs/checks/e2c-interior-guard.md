## E2c third-party interior guard - 31 October 2026 (offline only)

Implementation `373304a` adds a pure Core guard verdict and an isolated Runtime process-metadata reader. A match, invalid rule/mode or detection error forces the existing F0 view off even when requested on. No foreign implementation, binary, Workshop page or internals were accessed; no interop, new Harmony patch, resident behavior, native writer, A-stack dependency or save/schema change. Only user-supplied assembly-name defaults and optional configured Harmony owners are observed. The four parked hotspots are untouched.

The existing flat `<ModRootPath>/persistent-city.json` loader reads:

| Key | Default | Contract |
|---|---|---|
| `ThirdPartyInteriorGuard` | `"auto"` | Exact `auto` or `off`; off bypasses detection only. Unusable/unknown mode fails safe. |
| `ThirdPartyInteriorAssemblyPatterns` | `["TrueCityInteriors", "TrueCity*"]` | Case-insensitive ordinal exact name or one trailing `*` prefix, only simple loaded-assembly names. No type loading. |
| `ThirdPartyInteriorHarmonyOwnerIds` | `[]` | Optional exact, case-sensitive ordinal owner IDs. Empty means no method lookup or Harmony metadata read at all. |

Lists are bounded to 16 rules, each 1-128 characters, with no surrounding whitespace, empty/bare-star/interior-star patterns or wildcard owners. Invalid lists/values refuse safely rather than disabling detection. Empty assembly patterns intentionally turn off that input source; guard off intentionally ignores both inputs. Malformed JSON retains the existing loader failure policy. Edit unloaded and reload; no watcher, rewrite or schema field. The existing F0 setting/radius/caps/eligibility semantics remain intact when no rule matches.

`NativeInteriorCityView.Start`, called only from completed city initialization, scans the current process once. All enumeration is inside the pure verdict's exception boundary; missing/ambiguous vanilla owner-inspection methods and read exceptions refuse. The optional metadata targets are vanilla `BuildingManager.EnterBuilding` and `ExitFromBuilding`, already documented by F0; nothing patches or invokes them. Detection blocks F0 before its native-speed preparation/event subscriptions. Unload clears the cached verdict; a new completed load evaluates again. No assembly-load event subscription, reflection, scan, polling, formatting or allocations are added to any frame path. One city-load log line records detection/reason/effective view, including when the requested F0 setting is off.

Bridge seam: read **`PopulationRuntime.InteriorGuardDiagnostics`** on demand. It returns cached verdict, matched rule/reason, effective configured view and cached active state; it deliberately does not call F0's refreshing `Active` getter or detection. Strings allocate only when this explicit diagnostic is requested.
