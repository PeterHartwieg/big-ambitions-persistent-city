## What F5a adds

- **`Core/PopulationCensus.cs`** (pure C#, netstandard2.1). `PopulationCensus.Compute(PopulationCensusInput)` reads places, the load-time business facts, residents and discovered station IDs and returns counts only: home interiors, beds, the 90% resident target, residents, households (occupied interiors), over-band homes, workplaces and area-band capacity, player-owned workplaces and capacity (separate line), unknown-area and unmatched workplaces, over-capacity workplaces, informational native rival staff, study places and capacity, resident workers, students, stations, commuter demand/target, day visitors per day, day-visitor pool demand/target and present visitors, visitor capacity and clamps, persisted persons, implied commute/visit trips and meal intents, and three consistency checks. `Summary()` prints canonical `key=value` lines plus a `hash=`; `WorkplaceDetail()` prints one ordinal line per workplace.
- **`PopulationCensusPolicy`** keeps every provisional value in one named constant: bands < 40 → 2, < 75 → 4, < 150 → 6, < 300 → 10, < 600 → 16, ≥ 600 → 24 (upper bounds exclusive; non-positive or non-finite area → 0), study ×2, `WorkFillPercent = 80`, `LeisureVisitorSharePercent = 15`, `DayVisitProbabilityPercent = 25`, visitor capacity `min(2 × residents, 100,000)`, persons ≤ 150,000, stations ≤ 256, places ≤ 20,000, three meal intents and two anchored trips per person-day.
- **Runtime.** `GamePlaces.Read(List<CensusWorkplace>?)` records, in the existing loop and from the existing catalogue dictionary, each established business's `BuildingSizeData.squareMeters`, `RentedByPlayer`, paired study place ID and (for rival businesses only) the `aiEmployees` list length. `Read()` without a sink is unchanged, and the sink changes no returned place. `PopulationRuntime.TryStart` keeps a detached copy of the **fresh load-time place catalogue** (ID, kind, capacity, area) and that business list for the session; the census never uses the persisted catalogue, which can predate businesses established since the city was saved. Residents' saved home and day assignments join that catalogue by stable place ID. Simulation and save places are unchanged. `Runtime/PopulationCensusDiagnostics.cs` registers the debug-console command `pc population census [workplaces]` (IngameDebugConsole `CommandHelper`, already referenced through `ExternalPlugins`). A request copies only managed facts on the main thread (three fields per resident, the discovered station IDs), runs the reduction, sorting and text building on a detached `Task.Run` worker, and publishes a result only while its originating save is still current. The command prints the latest finished result for this save (with `sequence`, `captured_minute`, `capture_ms`, `detached_compute_ms` and `next=pending|none`) and starts one new census if none is running; the first request in a session prints `status=pending`. Output goes through `Debug.Log` so FT `console` captures it. Station IDs come from `RouteObjectDiscovery.Stations` once a sweep is `Ready` (`discovered_stations=pending` before that), as `subway:<stationName>` with the same activity and DLC-visibility filter as `MultimodalRoutes.EnsureStations`. The route planner additionally drops stations without a finite navmesh entrance or near a gate, so its usable portal count can be smaller than `discovered_stations`.
- **Load-time facts.** Business facts and the catalogue are read once when the city starts. A business rented, created or converted later in the session appears in the census after the next load.
- **Unchanged:** `BusinessAllocation = 16`, every place capacity, the population, events, saves (writer 25), RLO and every native object. The census holds no state beyond the load-time catalogue copy, the business list and its latest result, and creates no person, wallet, employment or save field.

### F6 contract C1

Player-owned businesses (`BuildingRegistration.RentedByPlayer`) appear as `player_owned_workplaces` / `player_owned_capacity` with `player_owned_flag=excluded-from-assignment` and `owner=player` in the workplace lines. They are excluded from `workplace_capacity`, from the commuter formula and from the jobs-within-capacity check. Residents currently assigned there are counted in `resident_workers_player_owned`. No assignment changes; F5e applies the exclusion. The choice is `PopulationCensusPolicy.ExcludePlayerOwnedWorkplaces = true`.

## In-game checks for the next batched rig

Every check runs in the headless agent rig ([PeterHartwieg/big-ambitions-agent-rig](https://github.com/PeterHartwieg/big-ambitions-agent-rig), read-only for this slice) on named disposable FT cities with the F5a build staged through RIG-MODSET. RIG-LIVE (first live verification of the rig's flows, fixtures and mod set) is an infrastructure prerequisite of every check, not evidence. The rig records autosave, disables it in the isolated profile, verifies it is off before each measured window (including after reload) and restores it during cleanup. Explicit saves stay outside measured windows. No check is deferred to Peter, a playtest, an unlocked console or a by-hand visual check.

Every census read below means: run FT `console` with the line, wait at least 10 frames, run it again, and use the second output. That output's `sequence` must be newer than any earlier read, and its `next=` value is recorded.
