## What F5f adds

- **`ActiveJourneyIndex` in `Core/PhysicalJourneys.cs`** (pure C#, netstandard2.1). A derived, in-memory set of the persons whose phase can make them a physical-body candidate: `Travelling`, `WaitingForOpening` (door queues), `AtPlace` holding an optional stop, or `AtPlace` at `Leisure` in an outdoor scene place (`scene-…`). It is a superset of every stateful filter of the Runtime selection (moving journey, planned queuer, `Outdoor`); the time, distance, cooldown, RLO reservation, binding and cap filters stay in the selection. Membership lists use swap-removal, so filing is O(1) and enumeration allocates nothing.
- **Maintenance.** `CitySimulator` rebuilds the index at construction (load, reload, `RebuildRoutes`) and files a citizen wherever its live phase, activity, place or optional stop can change: at the top of `FileOptionalStop` (every committed event in `CompleteEvent`, `TryBeginMealVisit`, stop publication and conversation pairing) and in `TryBeginOptionalShopVisit`, the one live phase change that did not already file. Physical lease acquire/release, traffic completion, `ExtendMealStay` and retiming change only times. An event in flight works on a copy, so the live state (and the index) changes only at its commit; an abandoned event leaves both untouched.
- **Kind.** `ActiveJourneyIndex.KindOf` classifies the stable ID with F5b's `PersonIds` until F5c saves an explicit kind: `pv:<n>` and `consumer:<anchor>:<slot>` are visitors, every other ID (including test IDs of no person format) keeps today's resident behaviour. Visitors are indexed and counted (`WithheldVisitors`) but are never in `BodyCandidates` while `ActiveJourneyIndex.VisitorsReceiveBodies = false` — the one named switch for F5i. No writer-25 city contains a visitor-format ID, so in-game behaviour today is unchanged.
- **Runtime.** `PhysicalPopulation` candidate selection and `PlanQueues` iterate `simulation.ActiveJourneys.BodyCandidates` instead of every citizen. The filters, the full-pool early exit, `SelectionCandidate.ByPriority` (least recently attempted, nearest, ordinal ID), the four-attempt budget, caps (48/24/120 m) and lease calls are unchanged. The index is not in roster order; the comparer's ordinal-ID key is a total order for unique IDs, so the sorted candidates and the selected set are identical (tested with a reversed index order). Queue line and slot order were already sorted independently of enumeration order.
- **Shadow comparison and fallback.** At the first selection after construction (load, reload, route rebuild) and every `JourneyIndexCheckSeconds = 30` s, `PhysicalPopulation` checks `ActiveJourneyIndexMatchesState()` (the index equals a full scan, each person in the list of its kind) and that every citizen the selection's stateful filters could admit is indexed. A mismatch logs one warning and switches this session's selection to the full scan (`journeyIndexFallback`), which still withholds visitors. The 60 s physical diagnostics line now reports `journeyIndex`, `journeyIndexWithheldVisitors`, `journeyIndexChecks`, `journeyIndexMismatches` and `journeyIndexFallback`.
- **Unchanged:** lease authority and movement rules (F2 #89), spatial indexing (F2), body caps, saved state and writer 25, identities, wallets, meals, receipts and every native object. The index holds no saved field and makes no decision.
- **Build tooling.** At this base `tools/build.py` already failed in this worktree: 208 absolute source paths in the long worktree path put the csc command line past the Windows 32,767-character limit (WinError 206), independent of F5f. `tools/build.py` now passes the arguments through `build/csc.rsp` (outside the package folder); `-nologo`/`-noconfig` stay on the command line, and compiler options and inputs are unchanged. The resulting DLL (SHA-256 `f66196cd65980d4bb4e3b5ae5a4cf1cfd08be6a379f5b2f636d1c8d81b318e09`) is byte-identical to a build of the same commit from a short scratch path with the unchanged script. The E3 remaining-batch source check pins `tools/build.py`; its pin in `tools/e3-remaining-feasibility-regression/source-pins.json` is updated to the new content. The index class still lives in the existing `Core/PhysicalJourneys.cs`.

## Offline evidence (no game, rig, lease or ModsLocal)

- `tests/ActiveJourneyIndexTests.cs` (9 cases). Each comparison checks `ActiveJourneyIndexMatchesState()` and an independently written specification predicate (member set, kind lists, counts, no duplicates).
  - A 400-person mixed city (every persona, homes, work, schools, shops, leisure, four `scene-park:` places, optional stops at 100%): equality after **every committed event** (ActivityObserved), after **every single-event frame slice** for a whole day, after a **three-day hidden skip**, and after **save/reload** (same member IDs; both copies then advance identically and write byte-identical saves). Coverage asserted: travelling, optional-stop and outdoor-scene members all occur.
  - **Interrupted plans:** with a resumable planner, equality while each event waits for its route, between `ContinuePlanning` slices, and after `RebuildRoutes` abandons every seventh in-flight event and the replacement replays it.
  - **Physical lease / pool release:** equality after acquire, while frozen (others arrive and leave the index), after an observation, after reload while leased, after release and after arrival.
  - **Visit starts:** optional shop visit and meal visit each enter the index on departure, leave on arrival, re-enter for the walk back and leave at home (a mutation removing the new `TryBeginOptionalShopVisit` filing turns this red).
  - **Visitors:** `pv:` and `consumer:` persons are indexed and counted as withheld, never body candidates, also after reload and across a whole mixed day with one third visitor IDs.
  - **Superset:** every phase × activity × journey × optional stop × place combination that the Runtime stateful filters can admit is a member; membership equals the specification.
  - **No identity/economy effect:** two identical cities, one probing the index after every event, write byte-identical saves at three checkpoints; identities unchanged; `CityState.CurrentSchema == 25`; only `Contains` and `MatchesScan` are public methods (filing and rebuilding are internal).
  - **Drift detection:** a change made behind the simulator's back is a mismatch; refiling or rebuilding restores equality.
- `tests/PersonIdentityTests.cs`: F5b's inactive-identity source guard now allows `Core/PhysicalJourneys.cs` (the index) to reference `PersonKind` and `PersonIds` only; every other F5b name stays unreferenced outside the F5b files.
- `tools/physical-selection-regression` (production source blocks, real Core index, native doubles): on 500 randomized fixtures (up to 5,000 persons; travelling walk/car/subway, waiting, indoor, outdoor scene, queuers, prior attempts, reservations, bindings, failed acquisitions) the index selection equals the frozen pre-optimization baseline, the full-scan path and a reversed index order in selected IDs, order and cooldown writes, and samples no more positions than the full scan. Visitor fixtures (index and full-scan fallback) select no visitor and leave resident selection unchanged. Fixture correction: places are keyed by their own `Id` (as `PhysicalPopulation` builds them) and queuers are planned only for waiting citizens (as `PlanQueues` does). Prints `PASS 29575 checks; … F5f index-vs-full-scan selections 500`.
- Performance: [docs/perf/f5f.md](../perf/f5f.md).

Offline/headless success is not native proof. The harness does not run Unity, native bodies, NavMesh or RLO; it shows that the same production selection code returns the same candidates from the index as from the full scan.
