## What the code does

1. **Activation.** `PersistentCityMod.ResearchActivation()` builds the five checks: `ResearchAttached()`; `ResearchAgencyDialog.Installed` with an empty status; `ResearchBilling.Installed` with an empty status and a live session (a foreign patch found at midnight drops the session, so `Available` turns false); `ResearchMessages.ContractPassed`; and `simulation.Research` attached. Any failure makes `Available` false, and the C5e gate leaves the native campaign screen unchanged. `pcresearch status` prints each check and the first failed one.
2. **Delivery contract** (section 3.6). By reflection, with exact signatures, at initialization: `TextMessage(string, Dictionary<string,string>, bool, bool, bool, AdditionalMessageData)`, `Contact.SendMessage(TextMessage, bool, bool)`, the `Contact` fields `id`, `description`, `streetName` and `streetNumber`, `TextMessage.messageKey` and `messageData`, `GameInstance.Contacts` and `BuildingRegistrations`, `BuildingRegistration.BusinessName`, `businessTypeName`, `StreetName` and `StreetNumber`, `Address(string, int)` and `BuildingHelper.GetBuildingRegistration(Address)`. A mismatch turns research off for the session like a dialog or billing mismatch: `ResearchEligibility.SessionEnabled` needs all three contracts, so a saved Surveyed order is neither surveyed nor charged and stays unchanged in the save.
3. **Messages, once per order.** Before the bill, `ResearchNoticeTracker.Before` remembers up to 8 orders that are Surveyed. After the bill it hands one notice for each remembered order that is now Paid (delivery message) or Declined (decline message, for `InsufficientFunds` and `BalancePrecision`). Cancelled and PaymentUnknown orders send nothing. Surveyed → Paid and Surveyed → Declined happen once per order, so no saved state is added. A reloaded Paid order was never Surveyed at a boundary of that session, so it sends nothing. A boundary that ends with the runtime stopped forgets its orders and sends nothing.
4. **Send.** The business name comes from the registration whose `NativeFoodMarket.PlaceId` is the order's business. The agency address is parsed back from C5e's agency ID. The agency contact is the one native `Contact.GetContact` keeps for the registration at that address (same `id` and `description`); only if there is none is it a contact at that street address. No contact is ever created. The message is `new TextMessage(key, {businessName})` sent with native `Contact.SendMessage`. Failures are contained and counted (`messages skipped` in `pcresearch status`), and native `RunDaily` continues.
5. **Window.** The window opens from the Ctrl+F8 button or `pcresearch window open`. While it is closed, `OnGUI` checks one boolean and reads nothing. While it is open, the view is rebuilt on opening, on a new selection and at most once a second. Drawing lays out cached strings only. The view lists every order (open, delivered, closed) with product, business, price, order time and state. The selected order, or by default the newest Paid one, shows its report.
6. **Numbers only for Paid.** `ResearchReportText.Report` is the only caller of `MarketResearchReport.TryRead`, with the saved ledger as the entitlement. A non-Paid order, a Replaced one, or a report that does not belong to the ledger shows "No report numbers". A Paid report shows its coverage, survey time and logical day, one line per cell ("Croissant taste: somewhat high: 1,234"; unknown cells say "unknown"), then C4's `Evidence` text. `pcresearch report <id>` prints the same text. `pcresearch orders` and the window list never print cell values.
