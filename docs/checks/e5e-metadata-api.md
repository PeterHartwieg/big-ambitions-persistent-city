## Implemented contract

- Public provider handle with `TryRegisterProductMetadata(name, metadata, apiVersion, out reason)` and provider-wide `Dispose`. Optional scalar DTO inputs are validated/copied. Version 1 rejects incompatible versions without mutation. No item registration, Unity/native object, stock/price/recipe setter, provider callback or native write is part of this API.
- At most 256 product names, 256 provider IDs and separately 524,288 escaped-character/UTF-8 units including lifecycle/conflict bookkeeping. Exact ordinal canonical names and IDs have the 256 UTF-16-unit bound. Bounds reject before allocation/insertion; no truncation. Incremental conservative charges avoid whole-table serialization on edits. Retained managed bytes are measured separately.
- Identical same-provider values are idempotent. Replacement changes the provider's whole optional-field set atomically. Multiple within-budget providers for one name invalidate all API claims for that name, including equal claims; every permutation uses `conflicting-providers`. Conflict claims remain bounded bookkeeping, with no first/last winner. Provider removal heals only in the next publication. Disposed/unload-invalidated handles cannot register again.
- Registration/removal stage under a lock, including before PC initialization or from workers. Explicit host-main-thread publication produces detached immutable images and filters through a copied immutable host loaded-name image (16,384-name bound), independent of the E5a builder/reader. No native scan, reflection, polling, frame participant or provider code execution. Unavailable/null/missing loaded-name evidence contributes no API metadata. Runtime shutdown clears state and invalidates handles.
- E5c resolver composition implements valid config field > API field > defaults, including missing/rejected fields and rejected whole entries. Config round trips preserve absence; endpoint clamping remains explicit config. Original-three saved tastes/classes/fits remain authoritative. Per-field sources and API rejection/absence reasons are available for explicit diagnostics.
- `Capture` copies resolved scalars into E5d's existing revision-2 tuple. Schema remains **25**. Persistence, historical readers, held DTOs, native market/ownership/supply and the executable dynamic-capability refusal are unchanged. E5b owns invoking the resolver at new uncaptured contexts and integrating native admission/handoff. E5e tests prove held projection/wire stability, not executable E5b replay or native checkout.
