## What changed

The E5a reader now runs in the game, in shadow. It builds and publishes shop images and the loaded-name image, and nothing reads them for a decision. `SupportedBusiness` still checks `FoodProducts.Known`, `MenuStatus` still reports `DynamicIntegrationRefusal`, and ownership, candidates, captures and checkout are untouched. Shadow failures never throw into the market: each one is recorded in the capability report and leaves the shadow idle.

- `Runtime/FoodContractStamps.cs` (game-free, linked into tests). `CollectionVersionReader<T>` reads a collection's private `int _version` through a `DynamicMethod`. Binding fails closed when the field is missing, renamed, static or not `Int32`. `FoodContractSelfTest` checks that add, indexer set and remove each move the version. `ShopContractStamp` holds the menu, price and furniture collections (reference, version, count), `businessTypeName` by reference, and the rented, established, for-rent and closed flags. A default stamp never matches. Also here: `FoodContractCapabilities`, `LoadedNameImage` with its builder, `LoadedCatalogueRevision`, and the coalescing `ContractDirtyQueue<T>`.
- `Runtime/FoodContractHooks.cs` (game-free). `FoodContractHookTable` pins the 23 Decision 1 members: E5a's 19, plus `ParseIntoItemInstance`, `TemporarilyClose`, `RemoveUnusedRetailPrices` and `ResetItemCached`. `FoodContractHintRouter` routes postfixes to the reader. At most one router is active at a time. Every install and every dispose advances `Generation`. A postfix with no active router does nothing, so a disposed city stays unreachable even if unpatching failed. A call off the main thread is counted and becomes one catalogue-wide hint at the next main-thread `Drain`.
- `Runtime/LoadedCatalogueLifecycleMembers.cs`. `Bind` checks each table row by declaring type, name, static-ness and exact parameter types. `Discover` keeps E5a's 19 in table order. `HarmonyPatcher` installs one postfix per row under its own Harmony id, `persistentcity.food-contract`.
- `Runtime/LoadedCatalogueEligibilityReader.cs`. It implements the hint sink with a reference index of registrations and an address index for furniture hints, which come from `ItemInstance.streetName`/`streetNumber`. It takes the stamp when a shop pass starts and publishes it with the image. `Visit` compares stamps once per discovery visit. The catalogue and loaded-name image publish in the same step. `Reset` drops every native reference, and `RetainedNativeReferences` reports what is left.
- `Runtime/FoodContractDiagnostics.cs`. A `NativeFoodMarket` partial with shadow start and stop, the visit, one reader unit per frame, and the `pc food contract` views. A `PopulationRuntime` partial with the console command.
- Wiring, one line each: `StartContractShadow()` after the existing price patch in the `NativeFoodMarket` constructor, and `StopContractShadow()` after `UnpatchAll` in `Dispose` (`Runtime/NativeFoodMarket.cs`). `VisitContract(place, reg)` in the existing discovery visit and `ContinueContractShadow()` after `DiscoverShops(64)` (`Runtime/NativeFoodCandidates.cs`). One route in `Runtime/VendorDiagnostics.cs`. The discovery file is not in the row's file list, but the row requires the stamp read "on every existing discovery visit", and that visit is `DiscoverShops`. F2d does not touch the file, and E5b3 owns it next.
- `tests/PersistentCity.Tests.csproj` links the two game-free files, two lines.

### Hint kinds

| Kind | Rows | Effect |
| --- | --- | --- |
| Catalogue (W11) | `OnItemsLoaded`, `RegisterModItem`, `UnregisterModItem`, `ResetStaticData` | Bump the catalogue revision and requeue every tracked shop. Repeats coalesce until a rebuild starts, and a hint during a rebuild discards it. |
| Registration (W8, W9) | `UpdateCachedAvailableProducts`, `AddItemInstanceToBuilding`, `RemoveItemInstanceFromBuilding`, `OnBusinessTypeChanged`, `Reset`, `TemporarilyClose`, `RemoveUnusedRetailPrices` | Mark that shop dirty, one queued unit however many calls. |

| Quantity (W1, W2, W3, W5 amount) | `SubtractFromStock`, `FillUpShowcaseShelfOrPointOfSale`, `ReduceFromCargo`, both `MergeCargo`, `MergeAmount`, `RefillSingleItemWithLimit`, `TryAddStockAmount` | Counted, never a dirty source (Decision 6). `ReduceFromCargo` removes a slot by calling `RemoveFromCargo`, which is a Holder row. |
| Unattributed (W7) | `ResetItemCached` | Counted. No owner is reachable from a `CargoInstance`. |

### Known limits

- Element writes in place (a price, a stock `itemName`, an amount) move no stamp. The tests pin this. E5b3's recheck owns them.
- The .NET 10 `Dictionary` does not move `_version` on indexer set or remove. The game's Mono `mscorlib` does (`TryInsert` and both `Remove` overloads, SHA-256 `9434e43d…b47a`). The tests therefore use a Mono-like dictionary double. The in-game self-test is the proof for the real type (rig check 1).
- Mono can inline a small native method into a caller compiled before the patch. A hint can then be missing. Hints only shorten latency, so the stamp and E5b3's recheck still apply.
- `tools/e5a-eligibility-regression/source_checks.py` asserts that E5a has no production caller and no Harmony in its files. E5b2 changes both by design, so that check no longer holds. The `tools/*-regression` suites are not run before release, and the coordinator can retire or update that check.

## `pc food contract`

FT cities only. Views: `status` (the default), `capabilities`, `hints`, `stamps`, `catalogue`. All read-only.

- `status`: shadow on or off, the authority note, the capability verdict and first failure, the catalogue revision, refusal, count and bumps, the loaded-name image revision and count, tracked and pending shops, stamp reads and mismatches, dirty units and coalesced marks, definitions and holders read, hooks installed out of 23, the router generation, and reader units with their max time and number at or above 30 ms.
- `capabilities`: one entry per Decision 12 capability. Three version readers, three self-tests, E5a member discovery, `availableProducers`, `pointOfSales`, and each of the 23 hooks.
- `hints`: per hook, its writer, signature, kind, install failure, calls, new units, coalesced and unknown owners.
- `stamps`: per tracked shop, the image refusal, offer count, published and current stamp, and whether they match.
- `catalogue`: revision, refusal, whether the image is current, and its exact names.
