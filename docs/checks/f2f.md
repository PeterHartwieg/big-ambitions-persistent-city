## What is implemented

- **`Core/PresentationGrid.cs` (new).** A pure Core map from 64 m X/Z cells to the body candidates of the active-journey index (visitors stay withheld, `VisitorsReceiveBodies = false`). A travelling member with a committed journey is registered in every cell its legs cross. A door wait, optional stop or outdoor scene is registered in the cell of its place, because that is the position `PositionOf` gives it and the position `PlanQueues` filters on. Query returns every member registered in a cell that meets the square around the focus, each once (generation stamp), in no fixed order.
- **Filed only from `ActiveJourneyIndex.File` and `Rebuild`.** No `File`/`Rebuild` caller changed. `File` on a member that stays a member re-files it only if its anchor changed: a different journey reference, a phase change between travelling and stationary, or a different place position. Committed routes are immutable, so a frame, a lease observe/release, a query or a shadow check never re-files (`FilingHappensOnlyOnPhaseOrJourneyChange`).
- **Runtime reads.** Selection and `PlanQueues` now take their roster from `simulation.ActiveJourneys.Grid.Query(focus, radius, nearby)` instead of `BodyCandidates`; after a shadow mismatch both still use the full `State.Citizens` scan. Every filter after the roster line is unchanged: the exact `Position.Distance(sampled, focus) <= radius` test, the cooldown/reservation/binding filters and `SelectionCandidate.ByPriority`, whose ordinal-ID key is total, so roster order cannot change the set or the order.
- **Shadow check covers the grid.** `ActiveJourneyIndex.MatchesScan` now also requires `grid.Matches(eligible)`: exactly the body candidates are filed, each with its current journey reference or place position, and every cell slot points back at its entry. A mismatch takes the existing F5f path (one warning, `journeyIndexFallback = true` for the session). The diagnostics counters `journeyIndexChecks`/`journeyIndexMismatches`/`journeyIndexFallback` therefore include the grid.
- **F2b boundary intact.** The selection and `PlanQueues` edits only change the roster line. `PlanQueues` still calls `QueueAtOpening` read-only, writes nothing through it, and no `CancelOptionalStop` call returns. `PresentationBoundaryTests.PhysicalRuntimeCallsOnlyTheReviewedSimulationMembers` passes unchanged (`ActiveJourneys` was already on its read-only list).

### Technical choices

- **Cells on X/Z only.** `Position.Distance` is 3D, so every point within the radius has |dx| and |dz| within it; the X/Z square is a safe cover. Height is ignored.
- **Conservative segment cover.** For each leg, per 64 m column, the Z span of the leg over that column is registered, widened by 0.01 m on both axes, so rounding in `Lerp` or in `focus ± radius` cannot drop a point on a cell edge. Legs within 1e-9 m of vertical register their whole Z span.
- **Unplaced members.** A member whose position the grid cannot resolve is returned by every query: travelling without a journey (the selection filters it out anyway), an unknown place, a leg spanning more than 4,096 cells or with a nonfinite end. This keeps the query a superset in every case instead of guessing.
- **Place lookup.** `ActiveJourneyIndex` takes an optional place-position delegate; `CitySimulator` now constructs it in its constructor with `FindPosition` (its own place table). This is the only `CitySimulator.cs` change: one line moved from the field initializer, because an initializer cannot reference an instance method.
- **Moved places are drift.** `PublishVendorPlace` can move a vendor place's position without filing anyone. If an index member stands at such a place, the shadow check reports a mismatch and selection falls back to the full scan; it never misses a candidate silently. No current member kind stands at a vendor place (vendor stays are outside the index), so this is a guard, not an expected path.
- **Large squares.** A query square covering more cells than the grid holds reads every cell once instead; still deduplicated.
- **Read-only public surface.** The grid is reached through the property `ActiveJourneyIndex.Grid`, so the F5f test pinning the index's public methods to `Contains`/`MatchesScan` stays unchanged. `PresentationGrid`'s public methods are `Contains`, `Matches` and `Query`; filing, removal and clearing are internal.
- **Two shadow levels.** The runtime check compares anchors and slot back-pointers (cheap, catches a missed filing). Tests and the regression tool also call the internal `Matches(members, recompute: true)`, which recomputes every member's cells from its legs or place.
- **One reused result list.** `PhysicalPopulation.nearby` holds the query result; `PlanQueues` and then the selection fill it in turn within one update. Neither loop writes to Core before it finishes, so the list cannot change under either.
- **Regression tool repairs.** `tools/physical-selection-regression` had not run since E6e (#145) and F7c: the vendor-stay block inside the extracted selection text tripped a pre-F5f assertion, and the `Route.Minutes` duration-read patch no longer matched `Model.cs`. Both are fixed (the assertion now checks only the reconstructed roster loop; the counter wraps the current `Minutes` getter), and the fixture gained the `vendorWaiters` field and `QueuePlanEntry.Line` that block reads.
