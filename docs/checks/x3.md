## Read behaviour

`SaveCodec.Read` reads schema 1. Any other number returns `DevelopmentSchema` with the existing "start a new city" message and the payload kept; this covers 2–36 (older development builds), 0, negative and larger numbers. The early authority probe (`RequireExecutableCapabilities`) and `DevelopmentSchemaOf` use the same rule. Strict refusal of malformed, over-bound and unknown data is unchanged.

Accepted risk (decision record): a development city saved at schema 1 by an older build may misread or fail to load after an in-place format change.

### Byte check of the change

Before flipping the number, the collapsed codec was run with `CurrentSchema` still 36 on the pinned `schema-36` corpus: both payloads loaded and rewrote byte for byte. At schema 1 the new corpus payloads equal the old `schema-36` bytes with exactly two fields changed, the envelope `"Schema":36` → `1` and the body's `Schema` column `[0,36]` → `[0,1]`. No other byte of the format changed.
