### Configuration contract

The installed template has one optional top-level `FoodProductOverrides: {}`. The existing `<ModRootPath>/persistent-city.json` loader parses it at initialization, with the city unloaded; edits require mod reinitialization (restart the isolated game process when needed), with no watcher or frame parser. A city reload within the same initialized mod instance does not reparse the file. The default template is empty. Example isolated metadata (not eligibility evidence):

```json
"FoodProductOverrides": {
  "foodtrucks:itemname_dumplings": { "MealClass": "Food" },
  "foodtrucks:itemname_choppedcheese": { "MealClass": "Food" }
}
```

Those exact Street Food definitions are examples of dynamic names, not a product allow-list or proof of a compatible building holder. Config does not load/register products, supply stock, change Street Food assets or authorize sales. Dumplings and chopped cheese receive seeded resident tastes and median fits unless explicitly overridden.

The table accepts at most 256 unique keys, each 1–256 UTF-16 units, nonwhitespace and without controls, invalid surrogates or the outcome delimiter `|`. No trimming, aliases, case folding or vanilla fallback. Escaped-JSON and UTF-8 budgets are independently bounded to 512 Ki each before materializing the resolver; the streaming parser uses conservative punctuation/small-scalar charges and actual BigInteger decimal lengths before clamping and does not retain raw whitespace or a second JSON tree. The unchanged outer loader still reads the config file as text. A duplicate/invalid key, wrong table type, duplicate top-level table or overbound table rejects the entire optional table and preserves unrelated config. It never takes a prefix.

Entry fields are exact `MealClass`, `TasteBand`, `BreakfastFitCents`, `LunchFitCents`, `DinnerFitCents`. Unknown or duplicate properties default that entire entry. Class strings are exact Unknown/Food/Drink/Bundle/NonFood; absent or invalid class resolves Food for a new product. Numeric strings and infinities retain existing endpoint conventions: taste integer 0–4, fits integer 0–5000; out-of-range values clamp, unusable/NaN/wrong-type/in-range fractional inputs default (seeded per-resident taste when TasteBand is unusable). Malformed JSON follows the existing whole-file failure path. Original-three overrides are ignored. One aggregate diagnostic per affected category is logged once at load, without raw values/names; repeated Resolve/Weight calls never log. `ReportUnloadedOnce` accepts a detached loaded-name set for a bounded inert-key diagnostic; supplying that image is deferred to E5a/E5b, with no new catalogue scan in pure E5c. Diagnostic serialization preserves absent TasteBand so a round trip cannot freeze one resident's draw; the loader never rewrites config.
