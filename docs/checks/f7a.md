## Implemented contract

- `Persistence/SaveCostDiagnostics.cs`: `SaveCostRecorder` with five contiguous phases (`Observe`, `Synchronize`, `Validate`, `Encode`, `Publish`). `Enter` charges elapsed time to the phase in progress, so phase ticks partition the measured span exactly. It records payload characters, UTF-8 bytes (the value the codec's cap check already computes) and UTF-16 storage bytes (2 × characters), optional streaming/semantic record counts, success, error and the phase in progress at close (the failing phase on refusal). It stores primitives only and allocates nothing per cycle.
- `SaveCodec.Write(state, recorder)` and `SaveSession.WriteTo(modData, state, recorder)` are overloads. The existing signatures pass `null`. With `null` the write path takes no timestamps (`cost?.` only); the serialized bytes are the same either way.
- Runtime (`Runtime/SaveCostStatus.cs`, small edits in `PersistentCityMod.cs`): `PopulationRuntime.SaveCostDiagnosticsRequested` arms or disarms one reusable recorder. `PrototypeSettings.SaveCostDiagnostics` arms it from startup; its default is the named constant `PrototypeSettings.SaveCostDiagnosticsDefault = false`. `PopulationRuntime.SaveCostDiagnostics` is an on-demand projection (built only when read, like `AccountingDiagnostics`) of the last save (sequence, phase ms, total, ≥30 ms flag, payload sizes, records, `recordCountMs`) and the last activation (background read/create/validate ms, main-thread completion ms and its ≥30 ms flag, payload characters, success).
- In `Save()` the recorder begins after the existing early-return guard, so `observe` covers `BeginAccountingObservations`, the RLO reread, `BeforeSave`, `CompleteCampaignsForSave`, `RefreshKnownOwnership` and the epoch check. Record counts run only when requested, after publication, outside the phase timers, and are caught so they never throw into native `Save`. The F1 call order, every refusal and the `Fail`/`StopAccounting` paths are unchanged.
- Activation timing is written once per completed load into primitive fields: three timestamps in the background task, plus the main-thread span of `CompleteInitialization` after the per-frame `IsCompleted` early return. Nothing runs per frame.
- `tools/save-cost/`: the representative fixture (`RepresentativeFixture.cs`, F3 integrated replay at 957×2, 5,000×2 and 50,000×2), E5d stress fixtures rebuilt through E5d's own helpers (`StressFixture.cs`), the measurement program and `measure.py`.
- Writer 25, every codec, reader, cap, key and `modData` layout are unchanged. No visitor identity is stored or invented (F5 B6). No F7b–F7f scope (epoch key, snapshot split, compact format) is included. Peter's section 9 questions are not touched by F7a.

## Offline evidence

- Unit tests (`tests/SaveCostDiagnosticsTests.cs`, 6): diagnostics on/off publish identical bytes across three saves of two independent replays, and `Write(state, recorder) == Write(state)`; all five phases covered and ticks partition the span, payload sizes match; a refused save (duplicate identity) records `Validate` as the failing phase, never enters encode/publish, and keeps the original payload reference; 1,000 recorder cycles allocate 0 B; the representative fixture gives the same bytes for the same seed, for 1 vs 64 events per slice, and different bytes for another seed; the 957×2 fixture crosses midnight (every budget posted for day 2), has natural histories (avg < 32 visits), anchors every consumer to a saved resident and round-trips byte-identically.
- Harness: every one of the 12 fixtures × 8 save calls asserted on/off byte equality, phase coverage, the partition and payload size. Representative hashes equal F3's retained integrated-replay `saveSha256` at all three sizes; stress hashes equal E5d's retained `afterSha256` for all eight recorded cases. Determinism: representative 957×2 and 5,000×2 and stress 957x2 and 5000x2 each built twice with equal hashes; seed 24 differs.
- Baseline (synthetic .NET 10): representative 957×2 is **2,333,388 characters** (4,666,776 UTF-16 bytes, 11,312/11,309 records), save p50/p95/max **46.10/87.19/87.19 ms**, read p50 205.22 ms, retained 4.124 MiB. Stress 50000x2 is 162,346,836 characters, save p50/p95 **2,036.83/2,293.39 ms**. **All 84 measured save samples are ≥30 ms and flagged** (save latency, not mod-work). Main-thread simulator construction reached **32.221 ms (2/7 samples ≥30 ms) at representative 50,000×2**, flagged as startup latency. Full tables, limits and representativeness notes are in the [performance record](../perf/f7a.md).
- Ordinary-play mod-work: F7a adds no per-frame work. The F3 integrated replay and posting experiments are unchanged code paths; no mod-work p95 or whole-frame claim is made here. Whole-frame cost stays tracked separately (F4 #91).
