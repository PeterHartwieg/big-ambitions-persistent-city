## Implemented contract

- `Persistence/SaveCostDiagnostics.cs`: `SaveCostRecorder` with five contiguous phases (`Observe`, `Synchronize`, `Validate`, `Encode`, `Publish`). `Enter` charges elapsed time to the phase in progress, so phase ticks partition the measured span exactly. It records payload characters, UTF-8 bytes (the value the codec's cap check already computes) and UTF-16 storage bytes (2 × characters), optional streaming/semantic record counts, success, error and the phase in progress at close (the failing phase on refusal). It stores primitives only and allocates nothing per cycle.
- `SaveCodec.Write(state, recorder)` and `SaveSession.WriteTo(modData, state, recorder)` are overloads. The existing signatures pass `null`. With `null` the write path takes no timestamps (`cost?.` only); the serialized bytes are the same either way.
- Runtime (`Runtime/SaveCostStatus.cs`, small edits in `PersistentCityMod.cs`): `PopulationRuntime.SaveCostDiagnosticsRequested` arms or disarms one reusable recorder. `PrototypeSettings.SaveCostDiagnostics` arms it from startup; its default is the named constant `PrototypeSettings.SaveCostDiagnosticsDefault = false`. `PopulationRuntime.SaveCostDiagnostics` is an on-demand projection (built only when read, like `AccountingDiagnostics`) of the last save (sequence, phase ms, total, ≥30 ms flag, payload sizes, records, `recordCountMs`) and the last activation (background read/create/validate ms, main-thread completion ms and its ≥30 ms flag, payload characters, success).
- In `Save()` the recorder begins after the existing early-return guard, so `observe` covers `BeginAccountingObservations`, the RLO reread, `BeforeSave`, `CompleteCampaignsForSave`, `RefreshKnownOwnership` and the epoch check. Record counts run only when requested, after publication, outside the phase timers, and are caught so they never throw into native `Save`. The F1 call order, every refusal and the `Fail`/`StopAccounting` paths are unchanged.
- Activation timing is also requested-only. Whether diagnostics are armed is captured when a load starts (`timeActivation`). Only then does the load take three timestamps in the background task and time the main-thread span of `CompleteInitialization` (after the per-frame `IsCompleted` early return), writing primitive fields once. An unrequested load takes no timestamps, writes no activation fields, and its projection stays `activation=null`. Arming diagnostics mid-load takes effect at the next load. Nothing runs per frame.
- `tools/save-cost/`: the representative fixture (`RepresentativeFixture.cs`, F3 integrated replay at 957×2, 5,000×2 and 50,000×2), E5d stress fixtures rebuilt through E5d's own helpers (`StressFixture.cs`, including E5d's maximum-escaping `encoding-max` case, where characters and UTF-8 bytes diverge), the measurement program and `measure.py`.
- Writer 25, every codec, reader, cap, key and `modData` layout are unchanged. No visitor identity is stored or invented (F5 B6). No F7b–F7f scope (epoch key, snapshot split, compact format) is included. Peter's section 9 questions are not touched by F7a.
