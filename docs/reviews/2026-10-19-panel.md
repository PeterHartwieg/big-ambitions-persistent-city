## Findings and adjudication

| Finding | Disposition and evidence |
| --- | --- |
| Student/workplace or worker/school assignment accepted on load, then generated a role-invalid journey | Confirmed with an isolated reproduction. The codec now checks day-place role against persona, permits missing assignments and rejects retiree day assignments. Reader/writer regressions verify original payload and RLO keys remain intact. |
| A shift beginning before opening was cancelled for the whole day | Confirmed independently. Parent shifts begin 07:45 ±15 minutes; 30 of 31 jitter values missed an 08:00 workplace every day. Citizens now retain the intended activity while waiting for an opening before its deadline. Daily and weekly regressions admit four work visits over four workdays. |
| First retry fix could omit same-place admission after an unreachable return-home route | Confirmed during re-review; that fix was rejected. Explicit `WaitingForOpening` now records admission exactly once when the venue opens. |
| First retry fix could lose the deferred deadline during a long return-home journey | Confirmed during re-review, including reload. Explicit waiting retains the original destination/deadline at the current physical entrance, without an unnecessary home journey. Slow and unreachable home routes cannot consume this pending activity. |
| Assignments can exceed walking tolerance or target disconnected places | Deferred assignment policy for the playable milestone. The existing contract preserves assignments and refuses/retries impossible journeys; it does not promise reachable assignment. Core also supports experimental multimodal routes, so a global walking-distance filter would be incorrect. README now makes this limitation explicit. |
| A venue captured closed remains closed in the frozen catalogue | Deferred with live venue refresh for the playable milestone. This is the disclosed static catalogue policy; no failed visit is fabricated. README explicitly identifies the effect on assignments. |
| Stale synthetic-contract test count | Corrected; CHECKS.md owns the current total. |
| Flare's Social Media prerequisite and recovery were unclear | Confirmed from RLO's `Settings.SocialMedia` readiness gate. README and inactive diagnostic now identify the setting. After dependency loss, re-enable it and reload the city; saved state is retained. |

The opening-wait codec also rejects active journeys, home targets, wake times at/after the activity deadline, and wake times when the destination is closed. Waiting remains a physical position at the current entrance; it is not a teleport or a fabricated admission.
