## Inactive contract and refusal boundary

`Core/AgencyOrders.cs` contains provisional typed request/agency/scope/quote/evidence contracts. Scope is an opaque placeholder, not a tier, geography or report format. Agency identity includes a **loaded-city session** and opaque binding; it does not claim native generation identity. Quote/evidence use exact `Money` units without arithmetic/casts or display rounding. A single shared `AgencyOrderBook` is the city coordinator: every prospective agency entry point must use that same instance. C3 creates none in gameplay. The lock serializes concurrent callers, and pending is set before any port validation, protecting reentrant clicks too.

First valid quote owns the immutable single slot. Further clicks (including a new request ID/other agency/changed terms) return that same quote/ID for explicit review; they cannot replace it or trigger payment automatically. Preflight refuses invalid agency/quote or insufficient funds. Charge moves `Quoted → ChargePending → Paid` only with entry plus matching request/agency/exact amount and nonempty native evidence; missing/mismatched evidence becomes `PaymentUnknown`. Definitive no-debit insufficiency/refusal leaves the same quote reusable. Exceptions before the entry marker restore Quoted; exceptions after entry become blocking PaymentUnknown. The port must mark entry **immediately before its first possible native mutation**, and must never retry/refund internally. No automatic refund, retry, delivery, report or reconciliation exists. Paid and Unknown have no reset API, so both block any further charge for this deliberately single-slot prototype. C5 owns multi-order lifecycle and durable ownership; discarding/recreating this in-memory object is never a recovery protocol.

`Runtime/AgencyPaymentPort.cs` implements only refusal and never invokes the entry callback. A native charge implementation would need proven exact balance/record evidence, durable request association (possibly native data, but **LEAD**, not demonstrated), retention/reload/crash boundaries, current agency/quote validation, and a verified way to attach the third option while preserving native campaign behavior. C3 does not grant authority to fill these gaps with direct money edits, a food receipt or a guessed agency method. The observed generic debit is a candidate for further proof, not permission to activate it.
