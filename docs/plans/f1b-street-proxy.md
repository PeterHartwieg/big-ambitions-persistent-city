## Independent vanilla audit

`CityBuildingController` has separate base/fade/hide/LOD renderer collections; property blocks and native LOD updates have independent writers. An ancestry owner label is useful metadata, not complete ownership proof. Mesh/material names and bounds establish neither shader compatibility nor clipping. Diagnostics must read shared meshes/materials only; accessing instantiated `material`, `materials`, volume `profile`, native setters or scene cloning is unnecessary and prohibited.

## One-shot bridge commands

On Unity's main thread, obtain the existing `Persistent City Runtime` component. Call `PopulationRuntime.ReadStreetProxyDoors(true, null)` and `PopulationRuntime.ReadStreetProxyInventory(true)`. Both default to `requested=false`: an omitted/false argument returns null before host/native reads or allocations. There is no setting, initialization hook, scheduler, event subscription or per-frame caller. Reflection-only bridge hosts can use:

```csharp
var host = UnityEngine.GameObject.Find("Persistent City Runtime")
    .GetComponent("PersistentCity.Runtime.PopulationRuntime");
var doors = host.GetType().GetMethod("ReadStreetProxyDoors")
    .Invoke(host, new object[] { true, null });
var inventory = host.GetType().GetMethod("ReadStreetProxyInventory")
    .Invoke(host, new object[] { true });
// Serialize returned metadata; enum names improve readability.
var json = Newtonsoft.Json.JsonConvert.SerializeObject(doors,
    new Newtonsoft.Json.Converters.StringEnumConverter());
```

Read `InteriorGuardDiagnostics` separately as before. The new commands report observations even when drawing is guarded off; they never refresh/override E2c or F0, enable drawing, instantiate materials/profiles or change native state. A stale/unready population host throws before scene access. A missing/transitioning interior returns an explicit refusal. `Complete` means the requested observation finished within its declared scope, not renderer eligibility. `Refusal`, `Eligibility`, `Decision.Failure`, `CandidateAvailable` and `Consistent` must all be retained; no positive field alone is an acceptance verdict. Inventory deliberately uses the same first entrance as F0 and labels its anchor explicitly; it is not silently retargeted to a different door.

The door command records size/version, layout instance/world matrix columns, every semantic id and candidate frame, floor/eligibility, cached guard state and supplied edge provenance. It refuses more than 16 doors/exits, 32 edge points, missing/foreign/special exits, negative/missing/duplicate ids, nonfinite frames, nonunit scale/reflection/shear and elevator/multi-height evidence. No native primary/available-door fallback is used. The candidate maps the first exterior frame's axes to its uniquely matching exit root's axes. Every other matched frame gets a position and rotation residual. Thresholds are **0.10 m** and **1 degree** (inclusive). These diagnostic thresholds are conservative proposals, not measured visual tolerances.

To test independent geometry, pass an `IReadOnlyList<StreetEdgePair>` as the second argument: each pair contains an independently identified feature and point label, and exterior/interior world-space positions. At least three noncollinear points spanning two distinct edges/apertures are required. The points must come from separately identified fixed jamb/window landmarks on both sides; do not apply the candidate transform to manufacture the interior samples. Keep the source object/feature identification with the dump. Duplicate labels, absent/nonfinite data, residual failure or insufficient independent constraints keep `Consistent=false`. Current animated door leaves, root axes, repeated doorway captures and AABB corners without independently verified feature correspondence are insufficient. Identification can be performed through existing bridge scene reads while locked if the fixed landmarks are unambiguous; otherwise record NEEDS-INPUT, rather than inventing a pair. Even `Consistent=true` is only geometry evidence; `RendererAvailable` remains false.

The inventory traverses loaded `SceneManager` scenes, including inactive objects, plus already-owned physical bodies. It loads no assets and does not enumerate persistent/unloaded scenes. Bounds use conservative **3D AABB/sphere intersection around the exterior entrance**, computed once then classified at 30/60/120 m. A mesh whose center is outside but whose bounds intersect is included. Crossing bounds are explicitly `Crossing`; there is no assertion of strict mesh clipping. Metadata includes kind, transient instance, bounded names, scene, bounds, enabled/active/static state, shared mesh/submesh/material/shader names, property-block presence, shadows and LOD/fade ancestry hints. A separate `OwnerMembership` resolves explicit loaded-scene `LODGroup` level references, `ViewBlockingEntity.renderersToFade/renderersToHide` and `CityBuildingController.Renderers` (base LOD set) / `lodVersion`, including owners outside renderer ancestry. Hints do not prove collection membership; these particular observed references do not enumerate every external owner. Static mesh marking excludes known moving/animated ancestors but does not prove shader/transform immobility; `StaticMembershipProven=false` always.

Counts distinguish active/moving owned residents, owned vehicles and native Gley traffic at each radius. Movement is instantaneous velocity >0.01 m/s, **not** observed displacement; paused or inactive bodies are not motion proof. Other native actor categories are not silently called represented residents. Lights near either interior/street (plus global directional lights), loaded-scene volume enabled/active/weight/blend/global/priority scalars, ambient/fog and main-camera view/projection matrices are metadata only. Volume profile values and property-block values remain uninspected; no profile/material instantiation occurs.

Limits: 64 scenes, 4,096 total roots, 65,536 visited transforms, 1,024 total metadata rows (renderers/bodies/lights/volumes), 64 components per node/ancestor, 64 ancestry levels/hints and 32 materials/submeshes per renderer. Owner discovery caps at 4,096 owners, 65,536 references, eight LOD levels and 32 membership labels per included renderer. Names truncate at 160 characters; transient instances distinguish rows within a dump, never persistent correspondence. A native list-return API may allocate its observed collection before its cap can be checked. Any cap, missing script, unreadable value or context change produces `Complete=false`, a refusal and **partial counts** (`CountsComplete=false`), never an empty successful inventory. The fixed cap may be insufficient for a real city; that is an explicit remaining rig question, not permission to increase it silently or infer coverage from a partial result. Export metadata only; no mesh data, asset or raw save is needed.

## Refresh and invalidation

Current diagnostics have **no scheduled refresh**. Every requested call captures fresh scalar/string DTOs synchronously and retains no native references/cache/resources after return. Re-run after enter/exit, reload/save-identity replacement, layout/version change, scene load/unload, camera/time/weather change or native LOD/fade/material changes when comparing evidence. Do not compare transient instance ids across loads. Save/reload and captures stay outside measured windows. Refused/partial observations cannot be reused as a complete catalogue.

A future renderer would first require a proven static membership contract and explicit loaded-scene lifetime. Proposed bound: build a separately capped immutable draw list on completed entry; invalidate it on all lifecycle/layout/scene changes and immediately stop drawing when identity/eligibility/guard is uncertain. Only cached scalar identity/guard checks and bounded drawing would run per frame, with no reflection/hierarchy scan. Unsupported LOD/fade/property-block/animated owners remain excluded unless their read-only validity contract is established; do not poll or fight native writers. Radius-crossing meshes must be omitted until owned clipping is proven, not drawn whole. Changes to light/material state need a proven event/revision contract or refusal; a periodic guessed refresh does not establish safety. Own resources would release on every invalidation/exception/exit. This is a bounded proposal, not installed code or an accepted renderer contract.

Remaining unknowns are exact live semantic ids and fixed-frame conventions; independent multi-edge residuals in the small shop; medium/large/elevator fixtures; complete renderer/owner coverage under caps (including persistent-scene coverage); strict clipping and facade/aperture occlusion; shared main-camera depth; material/property-block/LOD/shadow behavior; indoor lighting/volume influence; dynamic presentation coverage; and native one-shot cost. F2/F3 and customer entry remain outside this slice. The next step is the numbered [normal 6 Nov evidence checklist](../checks/f1b-street-proxy.md), not a guessed graphics implementation.
