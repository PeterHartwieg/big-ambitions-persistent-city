## Shared reader and isolation

[DirectStockShowcaseReader](../../Runtime/DirectStockShowcaseReader.cs) holds the single field-reading implementation and private-constructor pinned donut/cupcake descriptors. [DonutFeasibilityReader](../../Runtime/DonutFeasibilityReader.cs) retains its existing API; [CupcakeFeasibilityReader](../../Runtime/CupcakeFeasibilityReader.cs) is the second explicit facade. Both return detached snapshots with exactly the original raw field semantics and refusal messages. Stack-only intermediate fields avoid an extra snapshot allocation. No arbitrary item ID is accepted at the public boundary.

Call `CupcakeFeasibilityReader.Read(existingRegistration)` explicitly on the Unity main thread, using an existing controller field; never create a registration. No city scan, hooks, polls, update, bridge command, game caller or persistent native-data cache exists. Metadata binds on the first explicit diagnostic call and is shared by both candidates. Field reflection and bounded scans occur only during that requested read. Zero calls means zero reader work/allocations by source reachability, not an observed native frame claim. Do not retain registrations across reload.

Limits stay unchanged: 2,000 furniture entries, 128 menu/price rows and 128 cargo/producer/whitelist/tag entries. `DirectStockFieldsVerified` verifies the conservative field shape only. `Eligibility` always remains Unknown. `RawProductUnits` excludes storage; `RawBagUnits` and `RawCounters` include unstaffed counters and are shared business facts. There is no sale capacity, bag multiplication, reservation, recipe or nutritional inference. `Price` retains exact `Money.FromNative(float)` units; equipment names come from loaded definitions.

All original donut refusals remain: unsupported business/product shape, malformed/oversized/missing collections, missing/duplicate menu or price, invalid money, ambiguous furniture identity/comparer, mismatched equipment/whitelist, nonconsuming or alternative resources, workstations, shared outputs/cargo, nesting, overflow, counter/product overlap, nonbag cargo and absent direct shelf/counter. Empty raw product/bag cargo is known zero; a missing bag definition/cargo refuses. No atomicity against concurrent mutation is promised.
