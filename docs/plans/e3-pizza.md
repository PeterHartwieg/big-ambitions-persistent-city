## Conditional probe and STOP decision

[PizzaFeasibilityReader.Read(existingRegistration)](../../Runtime/PizzaFeasibilityReader.cs) delegates to the single [DirectStockShowcaseReader](../../Runtime/DirectStockShowcaseReader.cs) using a private-constructor pinned pizza descriptor. The only shared runtime edit is that descriptor line. Donut/cupcake/salad facades, read branches, output semantics and refusals remain unchanged. No arbitrary public product selector is added.

The hypothesis is **finished pizza stock on a loaded `ShowcaseShelf` whose whitelist contains the exact pizza ID**, with consuming resources and no converted/shared inputs or outputs. Observed equipment names are copied, never used as authorization. A non-showcase oven/workstation remains unsupported even if its cargo contains pizza. `rawpizza`, dough and other intermediates never substitute. If loaded inspection finds a different holder type or converted-input-only contract, stop; new evidence and separate review would be needed before broadening this probe.

Explicit Unity-main-thread invocation only, on an already existing registration; reselect after reload. No native setup, checkout seam, synthetic customer/order, hook, poll, timer, city scan, bridge command, gameplay caller or persistent native-data cache. `NativeFoodMarket.Buy` remains restricted to the current three products. Natural native checkout and settlement are observation-only: `ProcessCustomer` is a write path that creates random customer data.

Unchanged bounds: 2,000 furniture entries and 128 menu/price/cargo/producer/whitelist/tag entries. A detached `DirectStockFieldsVerified` snapshot proves conservative field shape only. `Eligibility` always remains Unknown. `RawProductUnits` excludes storage; `RawBagUnits`/`RawCounters` are one shared unqualified pool, not available meals, service capacity or reservations. Exact price is retained. Zero known cargo/bags is raw zero; missing cargo refuses. All existing malformed/ambiguous/oversized business/catalogue/price/holder/cargo/identity/money, shared-input/output, workstation, nesting, overflow and counter-overlap refusals remain. No atomicity across concurrent native mutation is promised.
