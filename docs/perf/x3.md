# X3 perf: save schema held at 1

No runtime change is expected: the writer produces the same bytes apart from the schema number, and the reader takes the same path for the current writer. The removed branches compared a constant schema and were always taken.

## Save size

| Fixture | Before (schema 36) | After (schema 1) |
| --- | --- | --- |
| Corpus `full.json` (`ChangeJournalTests.Fixture(5150)`) | 73,332 chars | 73,330 chars |
| Corpus `minimal.json` (`CurrentSchemaOnlyTests.City`) | 2,630 chars | 2,628 chars |

The two characters are `36` → `1` in the envelope and in the body's `Schema` column; every other byte is identical.

## Save and load time

Offline, Release build, `SaveCodec.Write` and `SaveCodec.Read` on the corpus `full.json` city, 200 samples after 20 warm-ups, base `649467b` and this head built side by side on the same machine. Two runs each; the machine was shared with other work, so the numbers are noisy.
