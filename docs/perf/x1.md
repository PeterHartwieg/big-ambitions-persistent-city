# X1 perf: build and full-suite time after deleting the pre-26 codec chain

Offline only, on the Windows dev machine, one sample each. Other worktrees on the machine were not paused, so the numbers are indicative. X1 changes no runtime code path: `SaveCodec.Read`, the current writer and every simulation path are unchanged. Mod-work frame timing is therefore unaffected and was not measured.

| Measure | Before (`300ddb8`) | After (X1) |
|---|---:|---:|
| `dotnet build tests/PersistentCity.Tests.csproj --no-incremental` | 9.3 s | 8.2 s |
| Full suite `dotnet test --no-build` (runner duration) | 9 min 35 s (4,350 cases) | 7 min 42 s (4,003 cases) |
| `Persistence/*.cs` | 14,894 lines | 8,107 lines |

The after full-suite run is the branch before its last two test-only fixes, which removed five more chain cases. The final suite has 3,998 cases.

The main gain is for agents. 20 fewer `Persistence` files and about 6,800 fewer lines there mean that a search for `SaveCodec`, a wire field or a schema constant no longer returns four parallel copies of the codec.
