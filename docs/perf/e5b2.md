# E5b2 measurements

## 9 November 2026: offline components only

These numbers come from foreground .NET 10 runs on the Mac (Release build, `Stopwatch` at 24 MHz, so about 0.00004 ms per tick). They measure the game-free code that the reader and postfixes run. They are not combined mod-work or whole-frame samples. No game, rig, autosave setting or lease was used. The standing gate still applies: combined mod-work p95 under 5 ms, every mod-work spike at or above 30 ms flagged, whole-frame timing reported separately. Rig check 4 in [the checks](../checks/e5b2.md#in-game-checks-for-the-next-batched-rig) measures it in game.

Command: `PC_E5B2_MEASURE=out.jsonl dotnet test tests/PersistentCity.Tests.csproj -c Release --filter FullyQualifiedName~FoodContract`. Each arm warms 1,000 calls, then times 100,000 single calls. The sample list is allocated before the allocation counter starts.

| Arm | Target | p50 ms | p95 ms | max ms | B/call | >= 30 ms |
| --- | --- | ---: | ---: | ---: | ---: | ---: |
| Stamp read and compare per discovery visit | p95 <= 0.0005 ms, 0 B | 0.000083 | 0.000167 | 0.038208 | 0 | 0 |
| Postfix `SubtractFromStock` (Quantity, counted) | <= 0.001 ms, 0 B | 0 | 0.000042 | 0.702833 | 0 | 0 |
| Postfix `AddItemInstanceToBuilding` (Registration, coalesced) | <= 0.001 ms, 0 B | 0.000041 | 0.000042 | 0.014084 | 0 | 0 |
| Postfix `AddToCargo` (Holder by address, coalesced) | <= 0.001 ms, 0 B | 0.000167 | 0.000167 | 0.022167 | 0 | 0 |

The stamp arm reads the doubles of the three registration collections through the bound `DynamicMethod` readers and compares them with the recorded stamp. That is the work `Visit` does for a tracked clean shop, without the native field loads. The postfix arms time the router entry, not Harmony's trampoline. I read the single 0.70 ms max on the quantity arm as scheduler or timer noise in one sample: p95 is at the timer floor and nothing allocated. Rig check 4 decides whether anything like it shows up in game.

Steady-state allocation is also asserted as a gate: `StampReadAndCompareAllocateNothing` and `RoutingAllocatesNothingInSteadyState` require 0 B over 10,000 calls.

## Clean frames

When the catalogue is published and the dirty queue is empty, `ContinueContractShadow` drains an empty off-thread flag, takes two timestamps and calls `Continue`, which returns before reading any definition or holder. `Visit` on a tracked clean shop reads the stamp fields and nothing else. Neither path allocates or uses reflection. The reader's `definitionsRead`, `holdersRead` and `passes` counters in `pc food contract status` let rig check 4 confirm that they stay flat across a clean window. Offline, this rests on the code path and the pure-component arms above. The reader itself is game-bound and was not run here.

## Not measured offline

- The startup cost of installing 23 Harmony patches in the `NativeFoodMarket` constructor. It happens once per city load, not per frame, and rig check 4 records it as a load event.
- Reader units in game. The E5b1 offline backlog gives the expected size, with unit p95/max of 0.0125/0.0194 ms ([E5b1 perf](e5b-complete-menu.md)). `pc food contract status` reports the max unit time and the count at or above 30 ms.

## Cheap wins

None taken. This slice adds work, and every new path is already constant time and allocation-free.
