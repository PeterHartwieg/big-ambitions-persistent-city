# F7d compact wire format: F7p decision record (6 November 2026)

Refs #94. Owner slice: City-audit F7p ([plan section 3.6](https://github.com/PeterHartwieg/big-ambitions-persistent-city/blob/docs-history-2026-11-10/docs/plans/f7-save-snapshots.md#36-prototype-plan-f7p)). Evidence: [docs/perf/f7p.md](https://github.com/PeterHartwieg/big-ambitions-persistent-city/blob/docs-history-2026-11-10/docs/perf/f7p.md) and [assets/f7p/matrix.jsonl](https://github.com/PeterHartwieg/big-ambitions-persistent-city/blob/docs-history-2026-11-10/docs/perf/assets/f7p/matrix.jsonl), offline synthetic .NET 10 only. This record chooses the encoding that F7d builds. It does not implement it. Nothing here changes `Core/`, `Persistence/`, `Runtime/`, writer 25 or any schema. F7d allocates its writer number at merge and migrates from the writer that is current at that time, through that writer's frozen reader. If F5c's schema lands first, F7d migrates from F5c's writer.

## Decision

**F7d uses candidate C: columnar compact JSON with a per-save shared route table and chained road-tag ranges, conditional on F7d meeting the section 3.1 pause, allocation and load ceilings.** Under section 3.6's pass criteria, no candidate met every target in this prototype (see the limits below). C is selected on bytes, exactness and identity grounds. Its grammar is the one in `tools/compact-format/ColumnarCodec.cs`. A compact `modData` string is a JSON object with a format tag and version, ordinal key, field-sequence (shape) and string tables, a route table and one root column. The column types are numbers (exact token text, or zigzag base-64 varints for tokens that are exactly the invariant spelling of a long or of `N.0`), strings (table index, or inline for a string seen once), booleans, nulls, objects, flattened lists, positional tuple slots, route references and road ranges.

D (C plus deflate and base64) is **not selected**. A stays as today's writer-25 JSON, which becomes a frozen reader once F7d lands (section 3.9). B is the same grammar without route and road handling.

## Why, from the numbers

1. **Exactness holds for every candidate.** All 52 rows (13 fixtures × 4 candidates) give zero field differences across 1,369 (encoding-max) to 16,257,595 compared fields per fixture. Each rewrites the source writer-25 bytes exactly, and decode → re-encode is byte-identical. Unit tests add number spellings that must not be normalized (`-0`, `-0.0`, `1E-05`, integers beyond `long`), control characters and non-BMP strings, varying shapes, shared routes and road ranges. Refusal is tested for an unknown format, version or field, a bad table index, an unknown tag and truncation.
2. **C meets both byte targets with margin.** It reaches 29.74 % of writer 25 at representative 957×2 (target ≤ 35 %) and 20.93 % (33,972,886 chars) at stress 50000×2 (target ≤ 64 Mi). It is 21–30 % on every ASCII fixture and halves UTF-8 bytes at `encoding-max` (411,368 → 204,649). Records stay under the 4,000,000 cap with table entries charged; the maximum is 3,775,940 at CF64.
3. **C over B.** The bytes are equal on every fixture, because no fixture carries a journey at capture, a vehicle route or a road leg; the route header costs 12 characters. Native cities do carry those (the October archive had 9,093 traffic links), and the section 3.4 design asks for shared immutable routes. C costs nothing measurable when they are absent and is unit-tested when they are present.
4. **C over D.** D's string is far shorter (9.0 % of writer 25 at representative 957×2), but the native save is gzip-compressed anyway. On that estimate, D saves only 1.3 % at representative 957×2 (186,988 → 184,634 bytes), 5.5 % at 5,000×2 and 2.8 % at 50,000×2. It saves 16–54 % only on the saturated stress fixtures. In exchange, D adds encode time: at representative 957×2, p50 rose from 24.7 to 37.7 ms in the first run and from 25.1 to 66.3 ms in the review-round run (p95 35.4 → 69.1 ms). It makes the payload opaque to inspection. And its bytes depend on the zlib build, so decode → re-encode identity and pinned corpus hashes (F7f) hold only within one runtime, not across CoreCLR and Mono.
5. **Memory.** Interning on decode gives C a decoded tree at 0.50–0.66 × A's retained bytes, against a target of ≤ 80 %. At representative 957×2 it has 8,230 distinct string instances against 37,088.

## What this prototype does not show (limits and gaps)

- **No candidate met every section 3.1 target.** C meets bytes, records and retained memory. It misses these targets ([composed phases](https://github.com/PeterHartwieg/big-ambitions-persistent-city/blob/docs-history-2026-11-10/docs/perf/f7p.md#against-the-section-31-targets-candidate-c-all-synthetic)):
  - **Typical pause:** synchronize 1.5 + capture proxy 7.8 + validate 11.4 + encode 25.1 = 45.9 ms p50 at representative 957×2, against ≤ 40 ms p95.
  - **Stress pause:** 1,796.9 ms p50 at 50000×2 (encode 1,374.6 ms), against ≤ 600 ms.
  - **Allocation:** 7.8–11.5 × payload UTF-16 bytes, against ≤ 2.5 ×.
  - **Stress load:** 3,514 ms at 50000×2 without the upper-bound materialization, against 2,500 ms.
- **The format itself adds encode work.** In the same harness, C encodes at 1.19 × A at representative 957×2 and 3.27 × at 50000×2 (1,374.6 vs 419.9 ms), 3.2–4.6 × on the other stress fixtures and 7.09 × at representative 50,000×2 (2,161.5 vs 305.1 ms). The full range is 1.19–7.09 ×. For scale, F7a's writer-25 `SaveCodec.Write` took 2,036.83 ms p50 at 50000×2 (encode 1,815.57 ms). A here only copies an already-built tree, so the ratio is overhead of the columnar format itself (interning, column grouping, varint packing), not just of the tree encoder. A typed snapshot writer avoids re-reading number text, but nothing here shows that it reaches 600 ms. F7d's planning must treat the stress-pause and allocation ceilings as open risks. F7d encodes from F7c's typed snapshot and carries all section 3.1 budgets as offline ceiling tests (section 4). If F7d misses a budget without dropping an invariant, it reports the measured gap and Peter's approved scope decides. The invariant always wins. F7e's overlap window (section 3.5) remains the conditional fallback for the pause.
- **The phase timings use proxies.** Capture is a detached tree copy, not F7c's capture from the live graph. Materialization is the strict writer-25 reader on text, an upper bound. Synchronize and validate are today's writer-25 phases.
- **Traffic and routes are unmeasured for size.** No fixture holds traffic definitions, journeys at capture or road legs. Definitions stay columnar (the section 3.4 default). Omitting them in favour of a fingerprint rebuild is not adopted, because nothing measured it and it would need byte-identical rebuild proof. Rig check 1 ([checks file](https://github.com/PeterHartwieg/big-ambitions-persistent-city/blob/docs-history-2026-11-10/docs/checks/f7p.md)) runs this harness on an extracted native payload, which closes the gap.
- **Native effect is unknown.** Shorter strings should shorten native `SerializeSaveGame` and compression. Only F7 rig checks 2 and 6 can show by how much. D should be reopened only if those checks show that native serialize/compress time per PC character outweighs D's added encode cost.
- **Fixtures** are synthetic: the F3-replay representative and the E5d saturated stress set. The F5 declared population is not available yet; F7d measures it.

## Questions for Peter (section 9)

F7p touches Q2 (shop history days) and Q3 (visit limit) only by reporting bytes per history family. It implements the defaults: keep 14 days and today's visit limit, and prune nothing. Both live in named constants (`CompactFormatProgram.ShopHistoryDays`, `RecentVisitsLimit`), and retention is not a format choice. For scale: at 50000×2, C carries `Citizens[].RecentVisits` in 8,000,010 chars (38,450,000 in A) and `Food.History` in 2,251,188 chars (12,359,027 in A). Q1 (saving notice) is untouched.
