# Delete comments

The comment ban lives in `tests/CommentBanScanner.cs` and `tests/CommentBanTests.cs`. Every comment the scanner finds must be listed in `comment-excuses.txt` (path, tab, category, tab, collapsed text). The entry count must equal `CommentBanScanner.Ceiling`. Each entry admits one occurrence. Tooling directives (shebangs, `# noqa`, `# type:`, pylint/pyright/mypy, pragmas, shellcheck, `<auto-generated>`, SPDX license headers, ReSharper disable/restore) are not comments and need no entry.

1. List the comments: the entries in `comment-excuses.txt`, plus any the scanner reports when you run `dotnet test tests/PersistentCity.Tests.csproj --filter CommentBanTests`. Skip paths the task excludes.
2. Read each comment in its code and put it in one category:
   - Tautology: repeats what the code already shows.
   - Stale: refers to code, plans, schemas or gaps that no longer hold. Check with `git grep` before you decide.
   - Excuse: lets a hacky implementation stand (placeholder data, a skipped check, a retry loop, a dead seam).
   - Decision record: an important, non-obvious decision about the code.
3. Act on each one:
   - Tautology or stale: delete it.
   - Excuse: delete it and file one issue per hack with `gh issue create -R PeterHartwieg/big-ambitions-persistent-city`. Title `Comment cleanup: <short problem>`. Body: file:line before deletion, the deleted text, the proper fix. Group comments about the same hack.
   - Decision record: write it into an ADR under `docs/decisions/` in the style of `2026-11-08-price-weight.md` (one decision, or a group of close ones, per file; link the code), then delete it. A new ADR file needs Peter's `docs-approved` label (`tools/md-ban.py`), so prefer adding to an existing ADR from the same area.
   - Python module docstrings that the script prints through `__doc__` are help text: keep them listed as `runtime-doc`.
4. Remove the deleted comments' lines from `comment-excuses.txt` and set `CommentBanScanner.Ceiling` to the new entry count.
5. Change no code beyond the comment itself: no logic, renames or reformatting.
6. Run `python3 tools/build.py`, `python3 tools/test-focused.py`, `python3 tools/md-ban.py` and `python3 tools/docs-links/check.py`. Put the category counts, issue links, ADR paths and lines removed in the PR description.
