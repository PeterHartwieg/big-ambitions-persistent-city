## Actions and result contract

Call through `{"rig":{"op":"e5b_proof","action":"...",...}}` in an existing flow. Every reply is `{before,after}`; refusals have `after.supported:false` and `after.refusal`. The top-level rig transport `ok:true` alone does not mean the action succeeded. Assert the returned state/refusal explicitly. Unknown action arguments are rejected. Reply bodies cap at 48,000 UTF-16 characters; reduce page size on a bound refusal. No mutation is automatically replayed after an uncertain reply.

If native state changes a faulted list, restoration refuses instead of overwriting native changes. Retain that refusal, stop the owned player and discard/reload its disposable copy through the lifecycle. Never represent that as a successful exact restoration. The helper neither writes native saves nor manufactures native ownership, people, orders or positive eligibility. No legacy forged setup is compiled into it.

## Observation and timing limits

Hooks observe actual native `RunMainGameTick`, PC `AfterNativeTick`, `ForceCompleteAllWork`, customer/hourly customer callbacks and PC recovery. They never invoke those operations to advance boundaries. Recovery is optionally absent on the pre-round-1 red build and is reported as absent; the other required hooks fail closed. Events retain selected authority desired/managed/suspended/generation/requested/from/until values, clock, orders, money, live interior-customer count and setup count. Cached emitted field getters avoid reflection invocation in callback paths.

The arm thread is captured. An off-main-thread callback increments an atomic invalidation counter and returns before touching Unity/native snapshots or event buffers; original execution and exceptions are preserved. Such a capture cannot prove complete native ordering or clean timing. Overflow, callback errors, timed exceptions and cross-frame scopes also invalidate evidence. Same-thread sequence numbers establish only the observed callback order.

The exact queue contract was inspected read-only by the root: `Helpers.DistributedWork<ValueTuple<BuildingRegistration,int>>._pendingWork` is the pending Queue; `HasPendingWork` reads its Count; ForceCompleteAllWork dequeues and invokes `_updateAction` until empty. Actual `BusinessSimulatorHelper.SimulateBusiness` receives that tuple and passes its registration/hour to SetUp. The probe binds only those exact typed fields/getters and records actual job callbacks with the raw queued hour. A changed contract refuses arm; no arbitrary ICollection is guessed. Status reports binding/contract verification, while actual runtime ending-work/thread/order assertions still require the collected native events.

Frame mod-work is the nested union of actual PC Update/AfterNativeTick plus the reviewed PC OnGUI, physical native callback and food suppression-prefix entry methods. These extra scopes emit timing counters, not per-target event storms. Status lists every bound/missing scope; missing/off-main/cross-frame scopes invalidate a combined gate. Original native game methods remain observation-only and are not counted wholesale. Native work forced inside PC stays in its inclusive scope. Nested tracing overhead remains included; `observerMs` measures only part of it and cannot simply be subtracted. Per-call recovery/drain/native durations use matching `call` IDs. Whole-frame wall intervals remain separate; no GPU/CPU attribution is claimed. The first/current partial frames are excluded; diagnostic frames are flagged and excluded by the analyzer. `analyze.py` produces distributions and every >=30 ms flag from a complete exported `{status,frames,events}` JSON object. It reports a numerical p95 comparison only, never automatic native behavior certification.

Native cargo/nested/color/order/history DTOs use the exact metadata-inspected persisted fields, without ItemCached or other native property expansion. Timestamp/history structures bind exact field-name sets before timing and refuse changed types. Financial floats retain round-trip text and/or raw IEEE single-precision bits; no cents rounding is used to manufacture equality. Session-only weak order IDs distinguish actual order objects without changing them. Snapshot and production diagnostic work is excluded from clean windows; its elapsed cost is reported separately.

Before timing, independently record the original isolated autosave preference, disable/verify it off, check the `-rig-test` guard and verify again after reload. No save may occur inside a window; keep manual saves outside. Require root confirmation that task-owned .NET work is idle. Preserve/restore preferences and all preexisting rig files during lifecycle cleanup. These prerequisites are not implemented by pretending a probe status flag proves them.

Required native acceptance remains checks 3/4/6 in `docs/checks/e5b-complete-menu.md`: matched red/green isolation/recovery, real queue/customer ordering, exact transaction/receipt/accounting and replay, observation-only natural depletion/reload/refill shape, noninterference, recovery-wave p95 <5 ms and every >=30 ms spike with whole-frame separate. The prototype does not widen dynamic product authority.
