# PC small-store demand curve

Read-only diagnostic of the current food shadow model, executed inside the owned Windows agent rig. It creates its own disposable `FT` city, records one complete day of Persistent City's resident routines, reads native shop fields, and quotes native walking out and back. It selects a small food premise by the number of observed meal origins nearby, before calculating price outcomes; the seven nearest food competitors form the bounded market.

Every price replays the same cohort, routines, routes, competitor prices, service ratings and district signals. All eight shops receive **controlled** 15-meal/hour throughput and 10,000 hypothetical units per offer because actual staffed throughput and inventory are not established by the catalogue. One $18 allowance per resident/day is inherited from the current routine planner. Target menu prices span 50–200% in 5% steps. No native sales are booked. Native class price-acceptance methods provide a separate directional reference, not native transaction counts.

Follow `../..`'s AGENTS.md and the sibling Driven Rides `tools/agent-tests/README.md`. Read the Windows connection memory first. These scripts are deliberately pinned to the dated evidence directory and frozen validated candidate; use a new directory/owner for a new campaign, and never replace retained evidence. Never take another owner's lock or restore files while the player is running.

Order: acquire the dedicated `agent1` lock, `pc.py` (verified full rig-profile and preferences backup), `prepare.py` (PC references and frozen candidate build), `build_probe.py`, `run_pc.py`, then `plot.py <run-directory>` using Python with matplotlib. No ordinary game deployment is involved. The runner verifies the installed manifest, uses the native fast-forward control with bridge clock multiplier 1, and restores all preexisting rig files, its manifest and preferences before releasing ownership. A transfer failure is retained separately from a completed experiment.
