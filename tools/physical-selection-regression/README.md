# Physical selection regression

Run `python3 tools/physical-selection-regression/run.py` from any working directory with Python 3 and .NET 10 installed. The harness needs no game assemblies and writes generated sources/build outputs only under its own ignored `obj/` directory.

`baseline.json` freezes the relevant source blocks from the pre-optimization 27 October implementation snapshot. The runner extracts the current **actual** catalogue/slot admission block, physical-candidate enumeration through attempt recording (since 27 October a reusable candidate list with its `SelectionCandidate` struct and comparer, also extracted; the frozen LINQ baseline has no such block), `Ordinary`/`RandomAmbient` predicates, `Outdoor` predicate, hash helper and complete `SampleRoute` method. Both versions run against the same controlled fixtures. The remaining fixture code models eligibility inputs, successful/failed acquisition outcomes and native component query results; it does not reproduce an optimized selector. The full current Core source is also compiled, and its real `CitySimulator.SampleRoute` is invoked directly. A generated Model.cs copy adds only a duration-getter counter, keeping the sum unchanged.

Checks compare native slot identity/refusal, saved model/paint changes, complete attempted-ID order/cooldown writes and every sample backing field (including double bit patterns). Cases include mixed modes, stationary subway/car legs, indoor/outdoor/queue residents, equal distances, changing and off-axis focus (non-integer distances), many distinct past attempt times, exhausted separate caps, prior attempts/reservations/bindings, failed admissions, protected first inactive slots, unavailable models, empty ordinary catalogues, cold/warm model and paint initialization, 1–512-leg routes, endpoints/just-past-corner progress and mutable route legs. Call counts show eliminated position samples, hierarchy queries and repeated duration reads. Existing ownership and physical/traffic tests separately cover interrupted journeys and activation-time takeover.

This harness exercises production source blocks and the actual Core sampler; it does not run the complete Unity Update/TryAcquire lifecycle or establish native frame times, native getter purity, rendering or collision parity. Queue planning/rain policy, attempt/cap values, native activation ownership guards, cadence and route arithmetic remain production responsibilities.
