# Food demand diagnosis and scaling

This dated campaign compares the prior recurring-food build with the current candidate on the isolated PC rig, loading the same disposable `FT Food Routines Settled 20261022` checkpoint. It does not create customers or force buying decisions. `Probe.cs` attaches the optional Core decision observer and copies selected business, route, timing and choice inputs. The observer is absent from normal play and does not enter the save payload.

Read the home-PC memory and sibling Driven Rides rig guide, acquire the unique campaign reservation, and run `pc.py` for a fresh verified complete backup before any deployment. `prepare.py` freezes the baseline and copies current native references. `build_probe.py` builds against that frozen DLL. `session.py start` installs only in the agent profile. `run_audit.py baseline` captures one natural day. Preserve that source/package/helper before compiling the candidate; `update_helper.py r2` requires the owned rig to be stopped. `run_audit.py candidate` loads the same starting checkpoint. Dated backup paths intentionally refuse reuse.

`verify.py` checks native stock/bag/customer conservation, daily settlement and completed returns. `check_settled_reload.py` saves/reloads the completed candidate and deliberately replays a paid intention to check its saved receipt. The replay project reproduces the captured baseline's choices exactly, evaluates explicitly limited price/break sensitivities, and benchmarks direct choice versus the previous one-person experiment. `--scale <output.json>` runs the complete Core scheduler for 1,000/2,000/5,000 synthetic residents and eight shops, comparing conservative route pruning with the same planner without that bound, including purchase identity/order hashes. Use `DOTNET_TieredCompilation=0` for the recorded timing comparison; native pathfinding, market reads and rendering are excluded from these offline timings.

Always finish with `session.py restore`: retain evidence, stop the rig, restore and verify preexisting profile files/preferences/manifest, remove the diagnostic helper and release ownership. New disposable FT saves can remain; the normal game/profile is never a target. Evidence is ignored under `build/food-demand-audit-20261022/`; findings belong in `docs/reviews/2026-10-22-food-demand-audit.md`.
