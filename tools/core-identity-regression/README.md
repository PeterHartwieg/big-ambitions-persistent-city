# Core identity regression

This harness checks that the 28 October core identity change (cached routine hash states, cached opening windows per place, road tags decoded once per leg) changed nothing a resident does, and measures how much it allocates.

`Program.cs` builds a synthetic city of 600 residents and 1,011 places with daily, overnight and weekly opening hours, on a 31 by 31 grid of 50 m road sections with native `native:road:v1:` tags and a `TrafficNetwork`. A pure planner drives car owners along the grid and walks everyone else, refusing one request in thirteen. The city runs six days through `AdvanceFrameSlice` in quarter-minute frames with 24 events each. It writes a save at every midnight and once during the day 3 morning commute at the first frame with at least three cars in traffic, and reloads that save into a new simulator so committed car journeys rebind from their saved strings. It prints one JSON line with a digest of every `ActivityObserved` event, the SHA-256 of every save, digests of helper probes over the final city (routine slots, opening hours, destination choice, a 300-leg road mapping), and `GC.GetAllocatedBytesForCurrentThread` totals for the frame slices, for the planner inside them and for each probe. It uses only public APIs that exist before and after the change, so the same file builds against both trees.

Run `python3 tools/core-identity-regression/compare.py --baseline <copy of Core/ and Persistence/ from before the change> --output <dir>`. It builds the harness in Release against both trees, fails on any difference outside the allocation and timing fields, and prints both allocation records. `dotnet run --project tools/core-identity-regression/CoreIdentityRegression.csproj --configuration Release` runs the checkout alone.

The harness does not load Unity or the game. Its planner, network and hours are synthetic, so the byte counts describe this fixture rather than a game session, and the timing field is wall-clock time on whatever else the machine was doing.
